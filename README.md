# SWBD Baby Crib Rocker — Home Assistant

[![Открыть в Marketplace / HACS](https://my.home-assistant.io/badges/marketplace_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=eldarsudden&repository=SWBD-Baby-Crib-Rocker&category=integration)
[![Добавить интеграцию в Home Assistant](https://my.home-assistant.io/badges/config_flow_start.svg)](https://my.home-assistant.io/redirect/config_flow_start/?domain=swbd)

Пользовательская интеграция для прямого управления устройствами качания по
Bluetooth LE. ESP32, прошивка шлюза и MQTT не нужны. Home Assistant подключается
к качалке своим Bluetooth-адаптером.

Протокол перенесён из [Karpesh/swbd-ble2mqtt](https://github.com/Karpesh/swbd-ble2mqtt),
коммит `8f504214892896a07815f10bc756444f9ab8830a` (MIT).

Работа интеграции подтверждена на реальной качалке с Home Assistant 2026.10
и Bluetooth-адаптером на отдельном сервере.

## Требования

- Home Assistant 2026.10 с настроенной интеграцией **Bluetooth**.
  Автоматическая проверка выполняется с HA 2026.10.4.
- Встроенный или USB Bluetooth LE адаптер на хосте HA в пределах связи с качалкой.
  Для виртуальной машины нужен проброс адаптера, для контейнера — настроенный
  доступ HA к Bluetooth/BlueZ хоста. Сам по себе Bluetooth на телефоне с
  приложением Home Assistant не предоставляет такой доступ.
- Качалка должна рекламировать одно из имён:

| Имя Bluetooth | Модель |
| --- | --- |
| `SWBDdrv_mc1` | Паинька |
| `SWBDdrv_mc2` | Соня |
| `SWBDdrv_mc3` | Тихоня |
| `SWBDdrv_mc5` | Совушка |
| `SWBDdrv_mc0` | SWBD mc0, имя есть в конфигурации исходного проекта |

Совместимость определяется BLE-протоколом конкретной прошивки, а не только
названием модели. При добавлении интеграция проверяет характеристику и ответ.

## Установка

**Через Marketplace / HACS**

1. Нажмите первую кнопку в начале README и укажите адрес своего Home Assistant.
   В HA 2026.10 нужен установленный HACS; в HA 2026.11 и новее ссылка открывает
   встроенный Marketplace. [Подробнее о совместимости ссылки](https://contributors.home-assistant.io/marketplace/guides/catalog/#the-link-to-your-repository).
2. Подтвердите добавление пользовательского репозитория и скачайте интеграцию
   **SWBD Baby Crib Rocker**.
3. Перезапустите Home Assistant.
4. Нажмите вторую кнопку **Добавить интеграцию в Home Assistant** либо подтвердите
   автоматически обнаруженную качалку в **Настройки → Устройства и службы**.

Первая кнопка открывает установку файлов, вторая — настройку уже установленной
интеграции. Репозиторий добавляется как пользовательский; включение в общий
каталог Marketplace / HACS оформляется отдельно.

**Вручную**

1. Скопируйте папку `custom_components/swbd` в каталог конфигурации HA:
   `/config/custom_components/swbd`. Файл `manifest.json` должен оказаться
   непосредственно в этой папке.
2. Перезапустите Home Assistant.
3. Откройте **Настройки → Устройства и службы**. Подтвердите обнаруженную
   качалку либо нажмите **Добавить интеграцию → SWBD Baby Crib Rocker** и выберите её.
4. Если устройство не найдено, включите качалку, приблизьте адаптер и закройте
   приложение производителя или старый BLE-шлюз: устройство может принимать
   только одно соединение. Повторите добавление.

YAML и MAC-адрес вручную вводить не требуется. Каждая качалка добавляется отдельно.
Для удаления используйте меню интеграции в разделе «Устройства и службы».

## Управление

Для каждого устройства создаются шесть сущностей:

| Сущность | Значения |
| --- | --- |
| Качание | включено / выключено |
| Датчик движения | включён / выключен |
| Мощность качания | 1–6 |
| Чувствительность датчика плача | 0–5; 0 отключает датчик |
| Таймер: часы | 0–23 |
| Таймер: минуты | 0–59 |

Часы и минуты — части одного таймера самого устройства, а не расписание HA.
При изменении часов сохраняются текущие минуты, и наоборот. Изменение мощности,
датчиков или выключателя передаёт `FFFF` в поле времени, как в исходном проекте,
чтобы не перезаписывать таймер. Значение `0:00` передаётся буквально; его смысл
зависит от прошивки. Не используйте его как команду остановки — для этого есть
выключатель «Качание».

Показания поступают через BLE-уведомления; каждые 30 секунд HA дополнительно
запрашивает состояние. Перед командой состояние перечитывается, чтобы сохранить
изменения от физических кнопок. Сущности обновляются по ответу устройства,
а не по отправленной команде. При разрыве соединения они становятся недоступны;
опрос восстанавливает связь. Отправленные команды после ошибки не повторяются,
состояние до перезапуска HA автоматически не восстанавливается.

Постоянное BLE-соединение может мешать одновременному подключению приложения
производителя. Удалённые адаптеры, поддерживаемые HA и активные соединения, тоже
могут использоваться штатным Bluetooth API, но для этой установки ESP32 не нужен.

## Протокол и проверка на устройстве

Используются сервис `0000ffe0-0000-1000-8000-00805f9b34fb` и характеристика
`0000ffe1-0000-1000-8000-00805f9b34fb`. UUID `FFE2`–`FFE7` в исходном проекте —
виртуальные MQTT-параметры; запись выполняется шестибайтными пакетами в `FFE1`.
Запрос состояния — шесть нулевых байт. Проверяются длина, контрольная сумма
с переполнением `uint16_t` и диапазоны параметров; неизвестные биты сохраняются
с масками оригинальной реализации. Пятый байт пакета сохраняется без изменений.

После установки проверьте чтение состояния, изменение каждого параметра,
обновление после физических кнопок, восстановление после выключения питания
качалки и перезапуск HA. Если добавление завершается ошибкой, включите журнал:

```yaml
logger:
  default: warning
  logs:
    custom_components.swbd: debug
```

В журнале `Ignoring invalid SWBD packet` означает, что ответ не соответствует
ожидаемому формату. Для уточнения совместимости нужны модель, версия HA и
полученный шестибайтный пакет из журнала. Логи могут содержать Bluetooth-адреса.

## Разработка

```sh
python3.14 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest
.venv/bin/ruff check .
.venv/bin/ruff format --check .
```

Локально на macOS с Python 3.14.7 и Home Assistant 2026.10.4 пройдены 50 тестов,
проверка Ruff и проверка зависимостей `pip check`. Контрольная сумма сравнена
с отдельно скомпилированной C-функцией оригинала на 1002 пакетах. Для этого теста
нужен компилятор `cc` (на macOS — Command Line Tools).

Тесты используют настоящие классы HA для config flow, config entry, координатора
и сущностей; BLE-периферия имитируется. Проверены чтение и изменение параметров,
таймаут, обрыв соединения, повторное подключение, параллельные команды, ошибки
настройки и освобождение соединения. Эти проверки дополняют успешную проверку
интеграции на реальном устройстве. Совместимость с конкретной моделью и прошивкой
следует проверять на самой качалке.
